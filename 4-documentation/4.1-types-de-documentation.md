# Types de documentation

Un bon projet contient plusieurs types de documentation, chacun avec un but précis.

## Documentation de projet

### Pour qui ?
- toute personne qui découvre le projet.

### Objectif
- expliquer le projet,
- expliquer comment l’installer et le lancer.

### Exemple
- `README.md`
- `specs.md`

## Documentation technique

### Pour qui ?
- développeurs.

### Objectif
- expliquer l’architecture,
- documenter les choix techniques,
- faciliter la maintenance.

### Exemple
- `docs/architecture.md`
- `docs/api.md`
- `docs/decisions/*.md`

## Documentation utilisateur

### Pour qui ?
- utilisateurs finaux.

### Objectif
- expliquer comment utiliser le produit.

### Exemple
- `docs/usage.md`
- `docs/faq.md`

## Documentation de processus

### Pour qui ?
- toi-même dans le futur.

### Objectif
- garder une trace du travail,
- suivre l’avancement.

### Exemple
- `devlog.md`
- `CHANGELOG.md`

## Quand écrire

- README dès le début,
- architecture après les grandes décisions,
- API dès les premiers endpoints,
- usage dès que l’application fonctionne,
- devlog à chaque session.

## Conseil

Si c’est difficile à expliquer, c’est peut-être que la solution n’est pas encore claire.
