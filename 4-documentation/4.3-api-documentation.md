# Documentation d'API

Une documentation d’API permet à un autre développeur ou à toi-même de comprendre comment appeler le service.

## Que doit contenir un endpoint

- **Méthode et URL**
- **Description**
- **Accès** (public, privé, rôle)
- **Paramètres** (path, query, body)
- **Exemple de requête**
- **Réponse de succès**
- **Erreurs possibles**

## Exemple : `POST /api/auth/login`

**Description**

Permet à un utilisateur de se connecter et de recevoir un token.

**Accès**

Public.

**Corps de la requête**

```json
{
  "email": "alice@example.com",
  "password": "motdepasse123"
}
```

**Réponse succès (200)**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "abc123",
    "email": "alice@example.com",
    "name": "Alice Martin"
  }
}
```

**Erreurs possibles**

| Code | Message | Cause |
|------|---------|-------|
| 400 | `Email et mot de passe requis.` | Un champ manque. |
| 401 | `Email ou mot de passe incorrect.` | Identifiants invalides. |
| 500 | `Erreur interne du serveur.` | Problème serveur.

## Exemple : `GET /api/users/:id`

**Description**

Récupère les informations d’un utilisateur.

**Accès**

Privé (token requis).

**Paramètres d’URL**

- `id` : identifiant de l’utilisateur.

**Réponse succès (200)**

```json
{
  "id": "abc123",
  "email": "alice@example.com",
  "name": "Alice Martin"
}
```

**Erreurs possibles**

| Code | Message | Cause |
|------|---------|-------|
| 401 | `Token manquant.` | Pas de header Authorization. |
| 401 | `Token invalide.` | Token expiré ou incorrect. |
| 404 | `Utilisateur non trouvé.` | Identifiant absent.

## Conseil

Rédige la documentation en même temps que tu développes chaque endpoint. Ainsi, elle reste à jour.
