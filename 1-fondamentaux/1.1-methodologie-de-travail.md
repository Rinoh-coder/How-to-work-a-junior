# Méthodologie de travail pour développeur solo

Ce document te donne une méthode simple et efficace pour avancer sur un projet sans te perdre.
Le principe : travailler par petites étapes, tester souvent et garder ta base de code propre.

## La règle des 3P

- **Planifier** : décider ce que tu vas faire.
- **Produire** : coder et tester.
- **Polir** : relire, corriger, documenter.

## 1. Planifier

Avant de toucher au code, réponds à ces questions :

- **Quel est l’objectif précis de la session ?**
  Exemple : « Créer le formulaire de connexion et afficher une erreur en cas d’identifiants invalides. »
- **Quelles micro-tâches faut-il faire ?**
  Exemple : créer le formulaire, valider les champs, créer l’API, connecter le formulaire.
- **Quelles dépendances ou blocages existent ?**
  Exemple : besoin d’une base de données, d’une clé API ou de données de test.
- **Comment savoir si c’est terminé ?**
  Exemple : « Je peux me connecter avec un compte valide et voir un message d’erreur pour un mauvais mot de passe. »

**Résultat** : une liste de tâches claires dans `todo.md`, un ticket ou un document.

## 2. Produire

Travaille en petites étapes.

- **Une tâche à la fois** : évite de mélanger plusieurs objectifs.
- **Coder, tester, corriger** : dès qu’une tâche est faite, vérifie-la.
- **Commit atomique** : un commit = un petit changement cohérent.
- **Ne pas sur-architecturer** : fais ce qui est nécessaire maintenant.

Si tu bloques :

- cherche pendant 15 minutes,
- note le problème précisément,
- passe à autre chose si nécessaire,
- reprends plus tard avec une nouvelle stratégie.

## 3. Polir

Cette étape est essentielle pour que ton projet reste lisible et réutilisable.

- **Relis ton code** : les noms sont-ils clairs ? le code est-il lisible ?
- **Testes les cas réels** : au moins le scénario principal et un cas d’erreur.
- **Documentes ce qui a changé** : README, `devlog.md`, notes de la fonctionnalité.
- **Prépares la suite** : définis l’objectif de la prochaine session.

## Résumé rapide

- Planifie avant de coder.
- Travaille par petites tâches.
- Commit souvent.
- Revue et documentation à la fin.

## Astuce

Si tu reviens sur un projet après plusieurs jours, la première chose à faire est de relire ton dernier `devlog.md` ou `todo.md`.
