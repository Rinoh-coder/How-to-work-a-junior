# Organisation des dossiers

Une structure claire rend ton projet plus facile à comprendre et à maintenir.

## Ce qui compte

- un dossier = une responsabilité,
- des noms explicites,
- pas de dossiers vides inutiles,
- une profondeur raisonnable.

## Règles simples

### Un dossier par rôle

Chaque dossier doit regrouper un type de fichiers cohérent.

### Des noms clairs

- `controllers`, `models`, `components`, `services`, `utils`.
- `config`, `docs`, `tests`.
- évite `misc`, `stuff`, `temp`.

### Ne pas anticiper trop vite

Crée un dossier quand il sert réellement. Pas de structure inutile dès le début.

### Limiter la profondeur

Si le chemin est trop long, c’est souvent que la structure est mauvaise.

## Exemple de base

```
mon-projet/
├── src/
├── tests/
├── docs/
├── .gitignore
├── README.md
└── package.json
```

## Exemple frontend

```
mon-projet/
├── public/
├── src/
│   ├── components/
│   ├── pages/
│   ├── services/
│   └── utils/
├── tests/
├── .gitignore
└── package.json
```

## Exemple backend

```
mon-projet/
├── src/
│   ├── controllers/
│   ├── routes/
│   ├── models/
│   ├── services/
│   ├── middleware/
│   └── database/
├── tests/
├── .gitignore
└── package.json
```

## Choisir la bonne structure

1. Identifie les grandes parties du projet.
2. Crée un dossier pour chaque partie.
3. Place les fichiers au bon endroit.
4. Ajuste si la structure devient confuse.

## Conseil pratique

Si tu hésites entre deux dossiers, choisis celui qui décrit le mieux le contenu.
