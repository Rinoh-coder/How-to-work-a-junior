# Configuration du linting

Un linter analyse ton code sans l’exécuter pour trouver des erreurs et des incohérences.

## Pourquoi utiliser un linter

- détecte les erreurs tôt,
- uniformise le style du code,
- évite les variables inutilisées,
- aide à garder le code propre.

## Outils recommandés

### JavaScript

- `ESLint`
- `Prettier`

### Python

- `flake8`
- `black`

## Exemple JavaScript

1. Installer :

```bash
npm install --save-dev eslint prettier eslint-config-prettier eslint-plugin-prettier
```

2. Créer `.eslintrc.json` :

```json
{
  "env": {
    "browser": true,
    "es2022": true,
    "node": true
  },
  "extends": [
    "eslint:recommended",
    "plugin:prettier/recommended"
  ],
  "parserOptions": {
    "ecmaVersion": "latest",
    "sourceType": "module"
  },
  "rules": {
    "no-unused-vars": "error",
    "no-undef": "error",
    "prefer-const": "error",
    "eqeqeq": "error",
    "no-console": "warn",
    "semi": ["error", "always"],
    "quotes": ["error", "single"],
    "indent": ["error", 2],
    "comma-dangle": ["error", "always-multiline"],
    "object-curly-spacing": ["error", "always"],
    "array-bracket-spacing": ["error", "never"],
    "eol-last": ["error", "always"]
  }
}
```

3. Créer `.prettierrc` :

```json
{
  "singleQuote": true,
  "trailingComma": "all",
  "printWidth": 80,
  "tabWidth": 2,
  "semi": true
}
```

4. Ajouter des scripts :

```json
"scripts": {
  "lint": "eslint .",
  "lint:fix": "eslint --fix .",
  "format": "prettier --write ."
}
```

## Intégrer au workflow

- lance `npm run lint` avant chaque push,
- utilise `npm run lint:fix` pour corriger automatiquement,
- active ESLint et Prettier dans VS Code.

## Conseils

- commence avec des règles simples,
- si une règle bloque, ajuste-la raisonnablement,
- partage la configuration dans le dépôt.
