# Conventions de commits Git

Des messages de commit clairs rendent ton historique plus utile.

## Format recommandé

```
<type>(<scope>): <description>
```

### Types courants

- `feat` : nouvelle fonctionnalité.
- `fix` : correction de bug.
- `docs` : documentation.
- `style` : formatage ou style.
- `refactor` : réorganisation du code.
- `test` : ajout/modification de tests.
- `chore` : maintenance.

### Scope

Le scope indique la partie du projet : `auth`, `api`, `ui`, `db`, `config`, etc.

### Description

- impératif présent : `ajouter`, `corriger`, `mettre à jour`.
- concise et précise.
- sans point final.

## Exemples

- `feat(auth): ajouter le formulaire de connexion`
- `fix(api): corriger la validation du mot de passe`
- `docs(readme): documenter l'installation`
- `chore(deps): mettre à jour express`

## Commits plus détaillés

Si tu as besoin d’expliquer le pourquoi, ajoute un corps après une ligne vide.

```
fix(api): corriger la validation du mot de passe

Le serveur renvoyait une erreur 500 lorsque le champ était vide.
Maintenant il renvoie 400.
```

## Bonnes pratiques

- un commit = une action logique,
- si tu dois écrire « et », fais deux commits,
- relis tes commits avant de pousser,
- n’amende pas un commit déjà poussé.
