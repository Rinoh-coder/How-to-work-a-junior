# CI/CD pour développeur solo

CI/CD automatise les vérifications et t’aide à garder un dépôt fiable.

## Pourquoi c’est utile

- les tests s’exécutent automatiquement,
- le code non fonctionnel ne monte pas sur `main`,
- tu détectes les erreurs rapidement.

## Concepts clés

- **CI (intégration continue)** : vérifier le code à chaque push.
- **CD (livraison continue)** : préparer une version prête à livrer.
- **Déploiement continu** : envoyer automatiquement le code en production.

## Workflow recommandé

1. travaille sur une branche dédiée,
2. pousse ta branche,
3. le pipeline s’exécute,
4. si c’est OK, merge dans `main`.

## Ce que doit faire ton pipeline

- installer les dépendances,
- exécuter le lint,
- exécuter les tests,
- construire l’application si besoin.

## Exemple GitHub Actions

- `push` sur `feature/*` ou `develop` : lint + tests,
- `pull_request` sur `main` : lint + tests,
- `push` sur `main` : build + éventuel déploiement.

## Exemple minimal

```yaml
name: CI

on:
  push:
    branches: [develop, main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Installer Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install
      - run: npm run lint
      - run: npm test
```

## Conseils

- commence simple,
- regarde les logs quand ça échoue,
- corrige les erreurs avant de fusionner.
